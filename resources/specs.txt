CONFIGUREERBARE VELDNAMEN
-------------------------
TOBETESTED: Veldvolgorde is gebaseerd op Goodreads CSV export voor maximale compatibiliteit met Goodreads, Obsidian plugins (Booksidian, Book Search Plus) en andere boekencatalogus-tools.

TOBETESTED: De volgende velden zijn configureerbaar (in Goodreads volgorde):
TOBETESTED: 1. Field name cover: bijv. "coverimage", "thumbnail" (standaard: "cover") - UI: cover afbeelding
TOBETESTED: 2. Field name booktitle: bijv. "title", "naam" (standaard: "booktitle") - Goodreads: Title
TOBETESTED: 3. Field name author: bijv. "auteur", "writer" (standaard: "author") - Goodreads: Author
TOBETESTED: 4. Field name isbn: bijv. "isbn_nummer", "ISBN" (standaard: "isbn") - Goodreads: ISBN
TOBETESTED: 5. Field name rating: bijv. "beoordeling", "score" (standaard: "rating") - Goodreads: My Rating
TOBETESTED: 6. Field name publisher: bijv. "uitgever", "verlag" (standaard: "publisher") - Goodreads: Publisher
TOBETESTED: 7. Field name year: bijv. "jaar", "publication_year" (standaard: "year") - Goodreads: Year Published
TOBETESTED: 8. Field name language: bijv. "taal", "lang" (standaard: "language") - Extra: taal (niet in Goodreads)
TOBETESTED: 9. Field name tags: bijv. "genres", "categories" (standaard: "tags") - Goodreads: Bookshelves
TOBETESTED: 10. Field name series: bijv. "serie", "reeks" (standaard: "series") - Extra: serie naam
TOBETESTED: 11. Field name series_index: bijv. "deel", "volume" (standaard: "series_index") - Extra: serie volgnummer
TOBETESTED: 12. Field name description: bijv. "omschrijving", "samenvatting" (standaard: "description") - Goodreads: My Review
TOBETESTED: 13. Field name notes: bijv. "notities", "opmerkingen" (standaard: "notes") - Goodreads: Private Notes

TOBETESTED: Configuratie in customize/customize.txt prevaleert boven resources/customize.txt
TOBETESTED: Bij het parsen van markdown files: gebruik de geconfigureerde veldnamen uit customize.txt
DELETED: Als een geconfigureerde veldnaam niet gevonden wordt, probeer dan ook de standaard veldnaam als fallback. Nee, dat mag niet, hard coded veldnamen afvragen kan gekke dingen opleveren in combinatie met hoe mensen hun obsidian files gebruiken. Het is niet te voorzien welke situaties zich daarbij voordoen
TOBETESTED: Als men een foldernaam heeft ingegeven in customize/customize.txt, gebruik die dan. Anders, as men een foldernaam heeft ingegeven in resources/customize.txt, gebruik die. Anders, gebruik de meest recent gebruikte folder. Anders, gebruik de folder waar je je in bevindt. Als, na het volgen van deze logica, je een folder wilt tonen die niet (meer) bestaat, toon dan de folder waar je je in bevindt. 

YAML FRONTMATTER ONDERSTEUNING
------------------------------
TESTEDBYUSER: Detecteer YAML frontmatter (tekst tussen --- en ---) aan het begin van markdown files
TOBETESTED: AANGEPASTE LOGICA: Als YAML frontmatter aanwezig is, zoek eerst in de frontmatter naar [cover]/[booktitle]. Als die NIET gevonden worden in de frontmatter, doorzoek dan OOK de rest van het bestand (voor BookSpineScanner multi-book format waar frontmatter alleen scan-metadata bevat).
TESTEDBYUSER: Als GEEN YAML frontmatter aanwezig is, doorzoek dan wel het hele bestand naar platte key: value regels (huidige gedrag voor multi-book files)
TESTEDBYUSER: Parse YAML frontmatter met dezelfde veldnamen als platte key: value regels
TESTEDBYUSER: Negeer onbekende velden in YAML frontmatter (forward compatibility)
TOBETESTED: Voor Obsidian-compatibiliteit: ondersteun cover syntax met quotes en [[brackets]] en ook met embedding ![[exclamationmarkplusbrackets]], bijv. cover: "[[url]]"

VARIABELEN BESTANDSTYPE, DOCUMENTTYPE, COVER, BOOKTITLE, AUTHOR en ISBN
---------------------------
TESTEDBYUSER: Vul bestandstype met de extensie van je bestand (.epub, .pdf et cetera)
TESTEDBYUSER: Vul documenttype voor markdown bestanden: 1) met type: uit de YAML frontmatter, als die er is. Voor markdown bestanden zonder YAML frontmatter, vul hem met de eerste occurrence van type: in de tekst. Voor alle andere bestanden blijft deze variabele leeg
TESTEDBYUSER: Vul voor ebooks de variabele booktitle met de boektitel
TOBETESTED: Vul voor ebooks de variabele author met de author
TOBETESTED: Voor markdown files met YAML frontmatter: booktitle is de tekst achter "[booktitle]:". Als die regel er niet in staat, gebruik dan de tekst achter "[cover]:".
TOBETESTED: Voor book covers uit markdown files zonder YAML frontmatter (mogelijk staan er meerdere boeken in 1 bestand): als er na een regel met "[cover]:" en voor de volgende regel met "[cover]:" een regel staat met "[booktitle]:", gebruik die waarde dan voor booktitle. Dus bij: [cover], [cover], [booktitle]: alleen bij de tweede cover hoort een booktitle, de eerste heeft er geen. Als er geen aparte "[booktitle]:"-regel is gevonden, vul booktitle dan met de tekst achter "[cover]:".
TOBETESTED: Vul voor ebooks de variabele [isbn] met het isbn-nummer.
TOBETESTED: Vul voor markdown-bestanden variabele [isbn] vanuit de corresponderende regel in het markdownbestand. De logica is hetzelfde als voor [booktitle]. Dus: [cover], [cover], [booktitle], [isbn], [cover]: alleen voor het tweede boek is een isbn beschikbaar.
TOBETESTED: Vul voor markdown files de variabele author met de waarde uit regel "[author]:". De logica is hetzelfde als voor booktitle.

TOEGANKELIJKHEID (BEKENDE BEPERKING)
------------------------------------
TESTEDBYUSER: Kivy tekent zijn eigen UI (OpenGL-based) en gebruikt geen native OS-controls. Hierdoor kunnen schermlezers (NVDA, JAWS, Windows Narrator) de app niet voorlezen. Dit is een bekende beperking van het Kivy framework.
TESTEDBYUSER: Wel aanwezig: keyboard shortcuts (Ctrl+/-, F5, Alt+Left/Up), zoomfunctie, aanpasbare kleuren via customize.txt
TESTEDBYUSER: Voor een volledig toegankelijke app voor blinden/slechtzienden zou een ander framework nodig zijn (bijv. Qt met QAccessible, of een webapplicatie)

=== FASE 1: Tags lezen ===
TOBETESTED: Tags uit markdown YAML frontmatter lezen - formaat: "tags: [fiction, sci-fi]" of "tags:\n  - fiction\n  - sci-fi"
TOBETESTED: Tags uit markdown inline lezen (multi-book format) - formaat: "[tags]: fiction, sci-fi" (configureerbare veldnaam)
TOBETESTED: Tags uit EPUB metadata lezen - uit dc:subject elementen in OPF (was al geïmplementeerd)
TOBEBUILTNICETOHAVE: Tags uit MOBI/AZW metadata lezen - uit EXTH records (subject tags)
TOBETESTED: Tags uit PDF metadata lezen - uit Keywords veld (was al geïmplementeerd)
TOBETESTED: Tags opslaan in BookItem datastructuur als list[str] (was al geïmplementeerd)

TESTEDBYUSER: Alle andere bestandstypes worden ook meegenomen met basis info (filename, size, type)

TESTEDBYUSER: CLI support: python libiry2go.py [input] [output] [books_per_file]
TESTEDBYUSER: Output bestanden zijn compatibel met Libiry, Obsidian en andere markdown tools
